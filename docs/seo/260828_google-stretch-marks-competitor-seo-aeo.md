## 2. 三個競品的 SEO／AEO 分析

### 2.1 第 1 名：曜生婦幼診所

頁面：[認識與預防妊娠紋－聊聊孕產](https://www.ysobs2008.com.tw/information_text_546_%E8%AA%8D%E8%AD%98%E8%88%87%E9%A0%90%E9%98%B2%E5%A6%8A%E5%A8%A0%E7%B4%8B.html)

#### SEO 優勢

- title 直接包含「認識」「預防妊娠紋」與「孕產」，完全對應孕期知識意圖。
- 正文涵蓋妊娠紋成因、預防方法、好發部位、搔癢、顏色變化及產後淡化。
- 頁面正文是可讀取的 HTML，沒有把主要內容藏在圖片或互動元件中。
- 網站導覽清楚，有關於我們、醫師團隊、預約掛號、服務項目與婦幼衛教分類。
- 頁面及頁尾呈現新北新莊地址、電話與 Email，具備實體診所信號。
- 搜尋結果摘要能直接抽出「產後 3 個月至 1 年逐漸淡化」等內容，表示主題文字與查詢匹配度高。

#### AEO 優勢

- 使用多個接近使用者問題的段落標題，例如「如何預防妊娠紋出現？」「肚皮癢可以抓嗎？」「妊娠紋產後會變白色？」。
- 每個問題下方都有短答案，容易被搜尋摘要或 AI 擷取。
- 醫療機構與婦產科脈絡讓頁面具備比一般美容部落格更強的信任起點。
- 頁面不急著推銷療程，對廣泛知識詞較自然。

#### SEO／AEO 弱點與風險

- 本次抓到的 HTML 沒有清楚的 meta description、canonical、lang 或 JSON-LD 訊號；若正式頁面也是如此，技術 SEO 基礎偏弱。
- 可見標題主要是 H3，缺乏清楚的 H1／H2 內容層級。
- 沒有 FAQPage、Article、MedicalWebPage 或 Physician 等結構化資料可協助機器理解內容關係。
- 沒有明確發布日期／更新日期，且內容較舊，健康資訊的 freshness 不夠。
- 頁面列出的「孕期體重 10–14 公斤」「懷孕期間膠原蛋白流失是平時 10 倍」「按摩可消除妊娠紋」等說法，需要以目前醫學與孕期體重指南重新審查；醫療機構排名高不代表每個數字都可直接沿用。
- 主要外部資料來源是 GanKong 健康網，沒有在各個重要宣稱旁連結官方或原始研究。

#### 值得借鑑

1. 對廣泛詞先回答「是什麼、為什麼、如何預防」，不要一開始就只談療程。
2. 將問題拆成短段落，讓每段都能獨立回答一個搜尋問題。
3. 顯示真實醫療機構、地址、電話、醫師／科別脈絡。
4. 保持衛教與銷售的距離，先建立信任，再導向適合的專業諮詢。

### 2.2 第 2 名：粹究美學診所

頁面：[產後妊娠紋會消失嗎？醫美妊娠紋雷射消除療程效果與費用解析](https://tresure-clinic.com/stretch_marks/)

#### SEO 優勢

- title、H1、description 都大量覆蓋「產後妊娠紋」「消失」「雷射」「醫美」「療程」「費用」等高商業意圖詞。
- 有 self-canonical、`zh-TW`、robots index/follow、Open Graph 與 sitemap；本次抓到的頁面有完整技術基礎。
- 內容量非常大，包含妊娠紋定義、紅白紋、形成時間、前兆、部位、醫美療程、費用、FAQ、案例與延伸閱讀。
- 有 20 多個內容層級、22 個表格，將療程適合對象、次數、恢復期、費用與比較項目具體化。
- 有圖片、案例、諮詢顧問／醫師、站內醫美文章與療程頁形成主題集群。
- JSON-LD 同時包含 `Article`、`WebPage`、`ImageObject`、`BreadcrumbList`、`WebSite`、`Organization`、`Person` 與 `FAQPage`，語意覆蓋完整。

#### AEO 優勢

- 目錄直接列出使用者會問的問題：妊娠紋何時出現、紅白紋差別、會不會消失、妊娠紋霜有沒有用、雷射費用等。
- H2/H3 大量採用問句，適合 AI 逐題抽取答案。
- 有比較表與費用表，不只提供散文式介紹。
- FAQ 直接對應 PTT／Dcard 等使用者語言，擴大長尾詞覆蓋。
- 內容有「不能完全消除」的限制說明，而不是只做效果承諾；這有助於降低過度銷售感。

#### SEO／AEO 弱點與風險

- 頁面非常重：本次 HTML 約 450 KB、約 94 張圖片、48 個 script、300 多個連結。這不代表 Core Web Vitals 一定不合格，但很可能增加行動版載入、互動與爬取成本，應用 Lighthouse／PageSpeed 實測。
- 內容有重複目錄、重複區塊、用語錯誤與不自然句子，例如同一組導覽出現兩次、部分段落出現明顯編輯痕跡。這會削弱內容品質與 AI 摘要可信度。
- `妊娠紋` 關鍵字密度很高，標題、H2、表格、FAQ 與內鏈反覆出現，部分地方接近 keyword stuffing；應優先服務讀者，不要每個標題都重複完整關鍵字。
- 使用很多療程機型、波長、深度、溫度、價格與效果數字，但並非每個主張都有直接的原始研究或產品核准文件連結。
- `Radiesse`、微針電波、雷射波長、哺乳／產後黃金期、恢復期等內容屬高風險醫療與療程資訊，需確認實際核准用途、適應症、禁忌與文獻是否真的支持頁面表述。
- 有些句子把「可能改善」寫得接近「重建」「修復」「有效」，且以診所自有療程為解法；應把醫學證據、個案經驗與診所服務分開標記。

#### 值得借鑑

1. 用一頁覆蓋完整的搜尋問題集，而不是只寫一篇短服務介紹。
2. 使用「定義 → 分類 → 方法 → 費用 → FAQ → 諮詢」的內容順序。
3. 用表格整理不同療程，讓使用者能快速比較。
4. 建立醫師頁、療程頁、案例頁、知識文章之間的內部連結。
5. 在內容開頭與 FAQ 先回答結論，再說明限制與個體差異。

#### 值得借鑑

1. 用真實案例與療程前後影像增加 Experience，但必須補足案例條件與同意說明。
2. 把在地電話、地址、營業時間、LINE 放在服務頁中，縮短轉換路徑。
3. 服務頁可以簡潔，但至少要補一個清楚的療程比較、費用說明、風險與 FAQ 區塊。
4. 在 title／description 中加入地點與使用者最在意的問題，提升本地 CTR。

## 4. 與瑪菲斯雙和店目前頁面的差距

目前頁面：[妊娠紋有辦法消除嗎？妊娠紋消除費用、妊娠紋醫美選擇一次看！](https://clinic.i-image.org/stretch-marks-removal)

### 瑪菲斯雙和店目前的優勢

- title、H1、description 明確對應「妊娠紋消除、費用、醫美選擇」。
- 有紅紋／白紋、四大療程、部位、費用、恢復期、哺乳、反黑等完整長尾覆蓋。

### 瑪菲斯雙和店需要補強的地方

1. **要同時服務兩種搜尋意圖**：目前頁面偏醫美商業內容；若要搶廣泛的 `妊娠紋`，應另設中立知識主頁，先回答成因、自然變化、保養限制與何時就醫。

3. **補強證據對應**：40–80% 改善、紅紋黃金期、哺乳期、療程次數、價格等數字要逐一連到精確研究、官方資料或清楚的市場調查方法。
4. **改善 FAQ 語意**：目前 FAQ 使用自製 button 與 `display:none` 答案；建議改成 `<details><summary>` 或補上完整 ARIA 狀態。
5. **處理站內重複意圖**：`/article/stretch-marks` 與 `/stretch-marks-removal` 都談妊娠紋消除、療程與費用，需要重新分工、合併或 301。
6. **增加在地服務 Schema**：若要搶雙和／中和／新北相關搜尋，可在真實資料一致的前提下補 `MedicalClinic`、地址、電話、Geo、地圖、營業時間與 `sameAs`。
7. **控制商業語氣**：保留費用與 CTA，但將「推薦診所」「優質選擇」「複合療程效果更好」等內容與中立衛教、證據限制清楚分層。

## 5. 可直接採用的內容架構

### 5.1 知識型主頁：搶 `妊娠紋`

開頭先給 2–3 句直接答案：

> 妊娠紋是懷孕或皮膚快速伸展後形成的線狀紋路，常見於腹部，也可能出現在乳房、臀部與大腿。它可能隨時間變淡，但不一定完全消失；保濕可協助舒緩乾燥與搔癢，不能保證預防或移除妊娠紋。

建議 H2：

1. 妊娠紋是什麼？
2. 妊娠紋為什麼會出現？
3. 妊娠紋通常長在哪裡？
4. 紅色妊娠紋與白色妊娠紋有什麼不同？
5. 妊娠紋產後會自己消失嗎？
6. 妊娠霜、妊娠油或乳液有用嗎？
7. 什麼情況應先詢問皮膚科或婦產科？
8. 妊娠紋醫美療程有哪些選項？

### 5.2 商業型頁面：搶 `妊娠紋消除／費用／雷射`

保留目前 `/stretch-marks-removal` 作商業頁，架構採：

1. 先說明不能保證完全消除。
2. 紅紋／白紋分型。
3. 療程比較表：適用狀態、方式、次數、恢復期、風險與費用。
4. 醫師審閱與證據來源。
5. 哺乳、孕期、皮膚感染、用藥與禁忌的個別評估提醒。
6. 真實案例，標示日期、次數、拍攝條件與個案差異。
7. 雙和店 NAP、預約方式與諮詢前準備資料。

## 6. 後續優化步驟

### P0：索引、醫療信任與內容正確性

1. 重新定義 `/article/stretch-marks` 與 `/stretch-marks-removal` 的角色；必要時合併或 301。
2. 在正文顯示作者、醫師審閱者、專業資格、發布日、最後更新日與最後審閱日。
3. 逐項複核療效比例、孕哺安全、禁忌、療程次數、恢復期與價格。
4. 將每個重要數字連到精確研究、官方資料或可說明方法的價格來源。
5. 把診所推薦與醫療衛教分成清楚區塊，標示服務提供者與利益關係。

### P1：AEO 與使用者體驗

1. H1 後立刻放直接答案與重點摘要。
2. FAQ 改用語意化 HTML，加入 `aria-expanded`／`aria-controls` 或 `<details>`。
3. 將 FAQ 問題與長尾詞改成真正的 H3，答案第一句先給結論。
4. 期刊首頁連結改成對應的 PubMed、DOI 或全文研究。
5. 補上「妊娠紋、肥胖紋、生長紋、妊娠線、橘皮紋」的差異表，但避免不必要的關鍵字重複。
6. 補完整的 `MedicalClinic`、Physician、Article／MedicalWebPage 關係與作者頁連結。

### P2：主題集群與轉換

建立並互相連結以下長尾內容：

- 妊娠紋會自己消失嗎？
- 白色妊娠紋怎麼改善？

## 7. 分析方法與驗證流程

### 7.1 SERP 採樣

1. 固定查詢詞：`妊娠紋`。
2. 固定台灣、繁體中文、未登入狀態與裝置；記錄日期與時間。
3. 分別記錄廣告、自然結果、圖片、影片、People Also Ask 與 AI／摘要區塊。
4. 只把自然搜尋前三名列為主要競品；其他結果另列為內容參考。
5. 每月至少重查一次，確認搜尋意圖與競品是否改變。

### 7.2 技術檢查

- HTTP status、HTTPS、redirect、canonical、robots、sitemap。
- title、meta description、lang、hreflang、OG、Twitter Card。
- H1/H2/H3 層級、首段答案、正文是否存在 HTML。
- JSON-LD 是否可解析、類型是否貼合頁面、是否與可見內容一致。
- 圖片 alt、格式、尺寸、lazy loading 與案例圖說。
- 內部連結、作者頁、更新日期、地址、電話、營業時間與社群一致性。

### 7.3 內容與 AEO 檢查

- 搜尋意圖：知識、比較、交易、在地或混合。
- 是否在 H1 後立即回答主要問題。
- H2/H3 是否使用真實使用者問題。
- 是否有 FAQ、列表、表格、定義、案例與下一步行動。
- 作者、醫師資格、審閱日期、原始來源、案例條件是否透明。
- 孕期、哺乳、藥物、禁忌、療效與副作用是否有適當來源及個別評估提醒。

### 7.4 驗證工具與限制

Google 建議以 Rich Results Test、URL Inspection、Search Console 與 sitemap 驗證結構化資料、抓取與索引；結構化資料正確也不保證一定顯示 Rich Result。[Google 結構化資料說明](https://developers.google.com/search/docs/appearance/structured-data)、[Google sitemap 指南](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap)

Google AI Overviews／AI Mode 沒有獨立於一般 Google Search 的特殊技術門檻；可索引、可靠、以使用者為中心的內容，以及結構化資料與可見文字一致，仍是核心。[Google AI features](https://developers.google.com/search/docs/appearance/ai-features)

本次分析評估的是公開頁面訊號，不包含 Search Console 查詢、反向連結、實際 CTR、Core Web Vitals 現場數據或 AI 平台引用率。這些項目需由網站持有人帳戶與實際瀏覽器測試補足。

## 8. 最終建議

不要把瑪菲斯雙和店頁面單純改成「更長、更密集的關鍵字文章」。正確方向是：

> 以曜生的中立婦幼衛教建立 `妊娠紋` 知識入口，以粹究的問句、表格、FAQ 與費用結構服務醫美比較意圖，以馨美的案例與在地 NAP 強化轉換，再用醫師審閱、精確文獻與清楚限制建立瑪菲斯雙和店自己的可信度。

第一優先順序是解決頁面分工與 YMYL 證據透明度；第二優先才是補更多關鍵字與內容長度。Google 的 helpful content 原則也強調健康類內容需要更強的專業、作者背景、來源與可驗證性。[Creating helpful, reliable, people-first content](https://developers.google.com/search/docs/fundamentals/creating-helpful-content)
